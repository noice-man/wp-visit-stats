# WP Visit Stats — установка и настройка

## Для чего нужен плагин

WP Visit Stats — **упрощённая автономная замена Яндекс Метрики для базовых показателей**. Помогает сохранить независимую статистику посещаемости, если счётчик Яндекс Метрики отключён, заблокирован или недоступен. Не заменяет Вебвизор, рекламную атрибуцию, цели и остальные сложные функции Метрики. Если WordPress/сервер отключён, статистика также не записывается.

## Установка

1. Установите ZIP через **Плагины → Добавить новый → Загрузить плагин**.
2. Активируйте **WP Visit Stats**.
3. Откройте **Статистика визитов** в админке. Статистика станет появляться после посещений в браузере при соблюдении настроек приватности.
4. Проверьте страницу в режиме инкогнито без запрета DNT и затем загляните в отчёт за сегодня (зарегистрированные пользователи по умолчанию исключены).
5. В разделе **Статистика визитов → Настройки** укажите срок хранения (180 дней по умолчанию), настройте исключение авторизованных и ботов, при необходимости включите обязательное согласие.

## Если в списке материалов отображаются нули

В версии 1.0.1 исправлена загрузка счётчиков столбцов и учёт старых просмотров с нераспознанным ID записи. После обновления достаточно открыть список **Записи / Страницы** и проверить выбранные даты: исторические события без ID учитываются по permalink, а их привязка исправляется постепенно.

Если нули показываются **во всей аналитике**, проверьте посещение из приватного окна (по умолчанию авторизованные администраторы не учитываются), Do Not Track, настройки согласия и успешность POST-запроса `admin-ajax.php?action=wpvs_track` в инструментах разработчика браузера. Статистика не восстанавливает события, которые никогда не были записаны.

## Сбор данных и показатели

- Просмотр — успешный запрос из браузера к `admin-ajax.php` при открытии страницы. Скрипт отгружается локально, без сторонних CDN и API.
- Посетитель — уникальный случайный first-party идентификатор в HttpOnly cookie `wpvs_vid` (180 дней), в БД записывается только HMAC-хеш идентификатора.
- Сеанс — идентификатор в HttpOnly cookie `wpvs_sid`, переустанавливается через 30 минут бездействия.
- Сохраняются время UTC, календарная дата в часовом поясе WordPress, путь URL без query string, ID материала, домен источника, UTM source/medium/campaign, тип устройства, категория браузера. Полный реферер, сырой IP и полный User-Agent в БД не сохраняются.
- Метрики считаются по записям событий за выбранный период; посетители и сеансы — **точное количество уникальных хешей в доступных записях**, а не сумма по дням.
- Администратор выбирает период, видит ежедневный график, список наиболее посещаемых материалов, источники и устройства, последние просмотры.
- Для публичных CPT, записей и страниц в таблицах админки появляются сортируемые столбцы «Посетители» и «Просмотры» и поля периода.

## Настройка согласия

Плагин ставит аналитические first-party cookie, которые могут требовать согласия в зависимости от применимого законодательства и конфигурации сайта. По умолчанию параметр **«Требовать согласие» выключен**, поэтому владелец сайта должен оценить необходимость согласия и настроить баннер или систему CMP до применения на реальном сайте.

При включении **«Собирать только после согласия»** плагин останавливает все события, пока ваша система согласия не вызовет:

```javascript
window.WPVisitStats.grantConsent(); // нажата кнопка согласия
window.WPVisitStats.denyConsent();  // отзыв согласия
```

Согласие запоминается локально в браузере (`localStorage: wpvstats_consent`). Отзыв удаляет cookie на стороне сервера и останавливает дальнейший сбор; исторические обезличенные записи удаляются по сроку хранения, а не в момент отзыва. Добавьте этот порядок в политику конфиденциальности. До включения согласия интеграция с вашим баннером должна быть проверена.

## Расход ресурсов и ограничения

- Записи событий хранятся в отдельной таблице `{prefix}wpvs_events` без внешней СУБД.
- Каждая зарегистрированная страница — одна вставка в БД; на высоконагруженных сайтах потребуется оптимизация агрегатов.
- WP-Cron ежедневно удаляет старые события ограниченными пакетами. При отключённом WP-Cron настройте системный cron.
- Плагин не обнаруживает просмотры с выключенным JavaScript, блокировкой браузера или отказом от аналитических cookie. Известные боты исключаются эвристикой User-Agent — она не гарантирует полное исключение.
- Для прокси используется только серверный `REMOTE_ADDR` для ограничителя частоты; доверенные прокси необходимо правильно настроить на стороне сервера.
- Включён DNT — браузеры с активным Do Not Track не учитываются.
- Отчёт по отдельному материалу включает события, где URL совпал с permalink (не учитывает отдельные маршруты API и часть нестандартных SPA).

## Учёт целей (с версии 1.0.6)

Включите **Статистика визитов → Настройки → Учитывать цели WP Visit Stats**. Для самостоятельного события используйте `window.WPVisitStats.goal('zayavka')`. Его название будет доступно в **Статистика визитов → Цели**.

Если сайт уже отправляет JS-цели Яндекс Метрики через `ym(COUNTER, 'reachGoal', 'zayavka')`, можно включить **Зеркалировать вызовы ym()**. Плагин попробует записывать те же имена целей у себя, не передавая параметры `reachGoal` и не блокируя исходный код Метрики. Опция выключена по умолчанию. Автоматические и офлайн-цели Метрики не перехватываются. На сайте с кешем не забудьте обновить кеш HTML/JS. После включения протестируйте конкретную цель на тестовом событии от неавторизованного посетителя.

**Приватность:** цели подчиняются тем же настройкам согласия/DNT и сроку хранения, что и просмотры. Код цели может быть сохранён в отчёте — не используйте в нём персональные данные. Событие означает попытку вызвать `reachGoal` на странице, а не подтверждение регистрации конверсии сервисом Яндекса. Когда `ym` недоступна, для независимого учёта используйте `WPVisitStats.goal()` напрямую.
