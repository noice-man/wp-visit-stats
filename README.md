# WP Visit Stats — резервная аналитика для WordPress

**Лёгкая автономная альтернатива Яндекс Метрике для базовой статистики посещаемости WordPress.** Если счётчик Метрики недоступен или перестаёт работать, WP Visit Stats продолжает собирать события непосредственно на вашем сайте (при доступности самого WordPress).

Плагин не требует внешней аналитической платформы, ключей API или CDN: браузерный скрипт отправляет события в WordPress, где они сохраняются в собственной таблице базы данных.

## Новое в 1.0.5

- **Источники трафика**: сеансы распределяются по поисковым системам (Яндекс, Google и др.), социальным сетям (VK, Telegram, Дзен и др.), внешним сайтам, рекламе, email, кампаниям и прямым заходам. Есть доли и расшифровка конкретных источников за выбранный период.
- Для исторических данных используются сохранённые `ref_domain`, `utm_source`, `utm_medium`; миграция таблиц не нужна. Сеанс относится к источнику первого зарегистрированного просмотра **в выбранном периоде**.
- **Яндекс Браузер** теперь распознаётся по `YaBrowser/` отдельно от Chrome. Ранее записанные события уже содержат только классификацию браузера, поэтому задним числом не переименовываются.
- **Автообновления через WPR Update Hub**: клиент сохраняет запись WordPress `no_update`, даже когда новой версии нет или сервер хаба временно недоступен. Это позволяет отображать штатный переключатель автообновлений при наличии соответствующих прав и настроек WordPress; принудительно автообновления не включаются.

Сайт обновлений: https://ворд-пресс.рф/plugins/wp-visit-stats/ · [Релизы GitHub](https://github.com/noice-man/wp-visit-stats/releases).

### Проверка автообновлений

После ручной установки v1.0.5 откройте **Панель → Обновления → Проверить снова**, а затем **Плагины → Установленные плагины**. У WP Visit Stats должна быть доступна ссылка «Включить автообновления» (при наличии прав `update_plugins` и если эта функция не запрещена на сайте целиком). На multisite настройка доступна сетевому администратору. Включайте по желанию.

## Исправление статистики материалов в версии 1.0.1

Столбцы «Посетители» и «Просмотры» в списках записей, страниц и публичных CPT теперь загружают счётчики независимо от предварительного фильтра WordPress. Ранее собранные события без `post_id` учитываются по точному пути permalink; дополнительно плагин постепенно восстанавливает ID исторических событий при открытии списков материалов.

После обновления откройте **Записи → Все записи** или **Страницы → Все страницы** и проверьте выбор периода (по умолчанию последние 30 дней). Новые просмотры проверяйте в окне инкогнито: **посещения авторизованного администратора не считаются по умолчанию**. Если на сайте включены требование согласия, Do Not Track или фильтрация ботов, показатели могут оставаться нулевыми до появления допустимых событий. При нулевых значениях и на основном дашборде сначала проверьте отправку `wpvs_track` в Network браузера.

## Возможности

- Установка first-party cookie посетителя (180 дней) и cookie сеанса (30 минут неактивности); в БД только хеши идентификаторов.
- Запись каждой зарегистрированной страницы в отдельную таблицу, в том числе при HTML-кешировании сайта.
- Дата визита, путь без параметров запроса, ID материала, источник перехода (домен), UTM, устройство, браузер.
- Административный раздел «Статистика визитов» с выбором дат, графиком и суммарными метриками «Посетители», «Сеансы», «Просмотры страниц».
- Топ материалов, разбивка по устройствам, браузерам и источникам, последние просмотры.
- Виджет каналов трафика с поисковыми системами, соцсетями, переходами с сайтов, рекламой, email, кампаниями и прямыми заходами.
- Сортируемые столбцы «Посетители» и «Просмотры» в списках публичных записей, страниц и CPT, с фильтром периода.
- Не отслеживаются авторизованные пользователи по умолчанию; есть исключение известных ботов и поддержка Do Not Track.
- Режим обязательного согласия с JS API для интеграции с cookie-баннером.
- Автоочистка событий по установленному сроку (7–730 дней; 180 дней по умолчанию).

## Быстрая установка

1. Скачайте **[установочный ZIP](https://github.com/noice-man/wp-visit-stats/releases/download/v1.0.6/wp-visit-stats-v1.0.6.zip)** и установите через WordPress → Плагины → Добавить новый → Загрузить плагин.
2. Откройте «Статистика визитов».
3. Проверьте тестовое посещение в приватном окне (администраторы исключены по умолчанию).
4. Установите желаемый срок хранения, разберитесь с требованиями согласия и подключите баннер, если он нужен.

Полные настройки: [docs/SETUP.md](docs/SETUP.md).

## Что заменяет и чего нет

**Резервирует базовую статистику:** динамику посетителей, сеансов, просмотров; посещаемость конкретных материалов. **Не заменяет** Вебвизор, цели, e-commerce, карты кликов, подробные отчёты и рекламную атрибуцию Яндекс Метрики. Если весь сайт или база WordPress недоступны, этот плагин тоже перестаёт собирать данные. У разных счётчиков показатели могут отличаться из-за cookie, браузерных ограничений и правил определения сеанса.

## Приватность

События сохраняются в первом контуре WordPress без сырого IP, полного User-Agent, полного Referer и query-параметров URL. UTM значения и домены рефереров могут содержать пользовательские сведения при неправильной разметке ссылок, поэтому не помещайте персональные данные в UTM.

Cookie для аналитики могут требовать предварительного согласия. По умолчанию сбор активен; настройте согласие в соответствии с требованиями законодательства, прежде чем запускать плагин на реальном сайте. В режиме обязательного согласия вызовите `window.WPVisitStats.grantConsent()` / `window.WPVisitStats.denyConsent()` из вашего cookie-баннера.

## Цели и зеркалирование Яндекс Метрики (v1.0.6)

WP Visit Stats умеет учитывать отдельные события, используя свою таблицу `wpvs_goals`. Новые данные не смешиваются с просмотрами страниц, не меняют старые цифры и удаляются по установленному сроку хранения.

### Отправка собственной цели

```js
window.WPVisitStats?.goal('zayavka');
```

Виджет «Цели» появится на дашборде, а расширенный отчёт — в меню **Статистика визитов → Цели**. Доступны достижения, посетители и сеансы по каждому коду цели, динамика по дням и источники событий.

### Необязательное зеркалирование

В **Статистика визитов → Настройки** включите «Зеркалировать вызовы ym(..., reachGoal, ...)». По умолчанию выключено. Для вызова:

```js
ym(51634436, 'reachGoal', 'zayavka', {order_price: 1000, email: 'PRIVATE'});
```

WP Visit Stats зарегистрирует имя `zayavka` и номер счётчика `51634436`; объект с персональными и коммерческими параметрами **не записывается и не отправляется в WordPress**. Исходный вызов в Яндекс Метрику выполняется с первоначальными аргументами и callback, без дополнительного вызова `reachGoal`.

Это перехват **вызова JS API**, а не подтверждение обработки события сервером Яндекса. Не зеркалируются автоматически распознанные Яндексом клики, просмотры, скроллы, составные/офлайн-цели и события, произошедшие до установки перехватчика или после его перезаписи другим скриптом. Когда `ym()` недоступна, стабильной альтернативой остаётся собственная `WPVisitStats.goal()`; для важнейших конверсий надёжнее вызывать оба метода явно.

Зеркалирование не использует API-ключ Метрики и не требует отправки данных в Яндекс. При включённом согласии, DNT и исключении авторизованных применяются те же правила, что и к просмотрам. Идентификаторы целей принимаются только в формате `[a-zA-Z0-9_.:-]` длиной до 80 символов — не вставляйте в имя email, телефон или номер заказа. Для точной конверсии после успешной отправки формы устанавливайте цель по подтверждению результата, а не при клике.
